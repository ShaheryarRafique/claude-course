# Module 2 Content Research: Master the Claude App

Compiled from five parallel researchers (Anthropic official, articles, YouTube, Coursera, Udemy), August 2026. Anthropic sources are authoritative. Flagged facts must be re-verified on a live account the week of recording.

## Feature by feature: how to teach it, with real examples

### Interface (web, desktop, mobile)
- Runs on web, desktop app, and mobile (iOS and Android), all synced.
- Key control: the tools menu (slider icon) in the chat box toggles capabilities like web search.

### Conversations: edit, branch, regenerate (our differentiator, competitors skip this)
- Edit your message (pencil) to fork a branch; switch versions with the arrows. Retry forks a Claude reply, optionally on a different model. Star and rename key chats, archive finished ones.
- Teaching gold: editing an earlier message to branch is a context saver and the fix for "Claude hit the maximum length for this conversation." Most users never discover branching.

### Files and images
- Up to 20 files per chat, teach about 30 MB per file (the app; the 500 MB figure is the developer API). PDFs analysed visually to about 100 pages.
- Images: up to 20 per turn, put the image before the text, label multiples ("Image 1:"), aim for about 1000 px for legibility. Vision only interprets, it cannot generate or edit images.
- Example: "Summarise sections 2 to 4 in five bullets, and quote one line verbatim to prove you read it."

### Web search
- Toggle web search on in the tools menu, phrase as "Search the web for…", click citations to verify. On all plans.

### The triad: web search vs extended thinking vs research (Anthropic's best device)
- Web search: straightforward facts, one or two lookups (weather, news, a company).
- Extended thinking: hard reasoning that does not need the live web (math, debugging, planning).
- Research: comprehensive, five or more lookups, a cited report over a few minutes (paid).
- Build a "which do I pick?" exercise around this.

### Model picker and effort
- Haiku fast and cheap, Sonnet the everyday default, Opus for hard reasoning and coding, Fable for large autonomous work.
- Official tip: tuning the effort dial beats switching models. Do not put heavy models on light tasks. Extended thinking wastes tokens on lookups, rewrites, and greetings.
- VERIFY current app model names and numbering before recording (they drift fastest). Teach the idea, not a fixed name.

### Artifacts
- Output opens in a live side panel (Preview and Code). Created when content is significant and self-contained.
- Types: documents, code, single-page sites, charts and diagrams, and interactive tools.
- Flow to teach: write a specific prompt naming the format, iterate in the same chat ("make the font bigger"), highlight a section for a targeted edit with "Edit with Claude", browse versions with the version selector, then Publish and share a link. Remix copies a published artifact into a new chat.
- Example: a screenshot of a task board becomes a working interactive tracker in one prompt.
- Caution: the preview is a browser sandbox, external calls and storage may not work; a public link is open to anyone.

### Projects
- One Project per initiative. Set Instructions (role, tone, format, rules) and upload a tight knowledge base.
- Key mental model: chats inside a Project do not share context with each other, only the knowledge base is shared. Free plan is capped at about 5 Projects, paid adds automatic retrieval for large knowledge.
- Example instructions: "Audience: senior engineering managers. Tone: formal but approachable. About 1200 words, H2 and H3 only. Never invent citations. End each section with a one sentence takeaway."

### Memory (three layers people confuse)
- Standalone chats share one memory pool, each Project has its own separate memory, and incognito has none.
- It is extractive (a rolling summary), not a full transcript. Say "Add to memory: …" for an instant, explicit fact. Manage, edit, delete, pause, or reset in Settings.

### Voice and mobile
- Tap the voice icon, pick a voice, speak. Push to talk for noisy places. Reaches connected tools (calendar, email). Runs on Opus or Sonnet, not the largest model. Beta on all plans.
- Example: thumb typing on the train becomes push to talk while walking, and Claude reads its reply aloud.

### Power habits (the capstone)
- Match the model and effort to the task. Pick the right tool from the triad. Put durable context in Project knowledge, not repeated in chats. Curate Memory deliberately. Turn repeated outputs into a saved workflow. Always verify web answers via citations.

## Top beginner mistakes to teach against
1. One mega-project for everything, instead of one per initiative.
2. Assuming all chats in a Project share context (only the knowledge base does).
3. Hoarding 40 stale files (5 strong docs beat 40).
4. Expecting Memory everywhere and instantly (it is siloed and extractive).
5. Starting a new chat for each artifact tweak (iterate in the same chat).
6. Expecting a real backend from an artifact preview.
7. Publishing sensitive content to a public link.
8. Living on the biggest model with thinking always on (burns your limit).
9. Not knowing branching exists, and losing edited history.
10. Forgetting the web search toggle or not checking citations.

## What the market does badly (our openings, from Udemy and YouTube)
- Files, web search, voice, mobile, and conversation mechanics are footnotes, not lessons. We give each its own demo.
- Artifacts is taught only as a no-code app builder. We show the full range: docs, charts, and interactive tools.
- Model picker and extended thinking are shallow. We teach when to switch and when thinking pays, with side by side outputs.
- Projects and Memory are rarely shown working together over time. We demo persistence across sessions.
- Robotic AI narration and hollow quizzes are common complaints. We use warm human delivery, define every term on first use, and make quizzes earned.

## Structure lessons (from Coursera)
- Outcomes as: action verb plus specific feature plus concrete artifact ("Build a shareable dashboard as an Artifact").
- Short, video-heavy lessons, each with a hands-on imperative task, and one persistent real-world capstone (a Project with Memory).

## What we adopt for Module 2
1. Give every feature its own lesson and demo.
2. Make conversation mechanics (edit, branch, regenerate) a real lesson, since competitors skip it.
3. Teach the triad with a "which do I pick?" exercise.
4. Teach Projects, Memory, and incognito as a clean three-way contrast.
5. Make Artifacts hands-on: create, edit, version, publish, remix, covering docs, charts, and interactive tools.
6. One running example built across the module (a personal work or study Project), ending as the capstone: a Project with instructions, a knowledge base, Memory, and an Artifact.
7. Carry the 4D framework forward with habit-in-focus cues (Description for Project instructions, Discernment for verifying citations, Diligence for curating knowledge and memory).

## Verify before recording
Model names and numbering, file and image limits, exact edit and branch and regenerate button labels, voice option names, and plan gating (Projects cap, Deep Research, Live Artifacts, Chat search).
